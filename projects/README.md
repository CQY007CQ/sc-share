# 实验室项目提交规范

本目录用于实验室日常开源分享，集中展示成员愿意公开交流的实验、工具和项目。目标是让内容可查看、可运行、可讨论，并保留真实的分享与协作记录。

## 目录规则

```text
projects/
├─ shared/<项目英文简称>/                 实验室项目分享
├─ personal/<姓名拼音>-<项目英文简称>/    个人项目分享
├─ _template/README.md                      项目说明模板
└─ PROJECTS.md                              项目总览与接龙
```

目录名只使用小写英文字母、数字和连字符。每个项目必须有独立 README，不得把源码散放在 `projects/` 或仓库根目录。

## 最低提交要求

- 可公开的源代码，不包含账号、密码、Token 或个人隐私。
- 完整 README：背景、成员分工、环境、运行步骤、成果和后续计划。
- 依赖文件和一份可复现示例。
- 数据集、模型和第三方代码的来源及许可证说明。
- 至少一张真实运行截图，放在项目自己的 `docs/images/` 目录。

## 协作流程

1. 在 Gitee 创建 Issue，说明项目名称、负责人和计划提交内容。
2. Fork 仓库或创建 `project/...` 分支。
3. 只修改自己的项目目录和 `PROJECTS.md` 中对应的一行。
4. 提交 Pull Request，附运行方式和结果。
5. 根据评审意见修改，审核通过后由维护者合并。

分享负责人可以是组长或项目作者，负责整理材料、发起 Pull Request 并回应评审意见。项目成员和分工按实际情况填写，不夸大参与范围；其他同学可通过评论、Issue 和后续提交继续完善内容。
